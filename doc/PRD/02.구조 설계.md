# MeetPoint 구조 설계

## 1. 문서 목적

이 문서는 MeetPoint 기획안을 실제 서비스 구조로 연결하기 위한 구조 설계 문서이다.

현재 구현 기준으로 화면 구조, 시스템 구조, 데이터 흐름, 인증 구조, 추천 흐름을 한 번에 이해할 수 있도록 정리하는 것을 목표로 한다.

---

## 2. 구조 설계 개요

MeetPoint 는 Next.js 16 기반 웹 서비스로 구성한다.

핵심 구조 방향은 다음과 같다.

1. App Router 페이지 단위로 public 화면과 보호 화면을 분리한다.
2. friends 와 chat 을 핵심 앱 화면으로 두고, 채팅, 위치, 추천 흐름을 chat 안에서 통합한다.
3. 인증, 저장, 추천 계산은 Route Handler 와 Supabase 를 통해 처리한다.
4. 지도와 주소 검색은 브라우저 SDK 기반 UI 로 처리하되, 외부 검색 API 호출은 서버에서 대리 수행한다.
5. 모바일과 데스크톱 모두에서 동일한 핵심 사용자 흐름이 유지되도록 화면 상태를 확장한다.

---

## 3. 전체 시스템 구조

### 3.1 상위 구성 요소

MeetPoint 는 다음 요소로 구성된다.

1. 사용자 브라우저
2. Next.js 16 App Router 페이지
3. 클라이언트 화면 컴포넌트와 상태 훅
4. Next.js Route Handler
5. Supabase PostgreSQL
6. Kakao Maps JS SDK
7. Daum Postcode
8. Kakao Local API
9. Kakao Mobility API

### 3.2 역할 분리

| 구성 요소           | 역할                                                    |
| ------------------- | ------------------------------------------------------- |
| 브라우저            | 화면 렌더링, 입력 처리, 지도 인터랙션, 모바일 시트 제어 |
| App Router          | 랜딩, 인증, friends, chat, 소개 페이지 진입 구조 제공   |
| 클라이언트 컴포넌트 | 친구 선택, 채팅, 위치 상태, 추천 결과, 지도 UI 표시     |
| 상태 훅             | friends/chat/recommendation 화면 상태와 상호작용 제어   |
| Route Handler       | 인증, 친구, 메시지, 위치, 추천 요청 처리                |
| Supabase            | 사용자, 친구, 메시지, 저장 위치 영속 저장               |
| Kakao Maps JS SDK   | 지도 렌더링, 마커 표시, 핀 지정, 전체화면 지도          |
| Daum Postcode       | 주소 검색 UI 보조                                       |
| Kakao Local API     | 장소/주소 검색                                          |
| Kakao Mobility API  | 추천 길찾기 카드용 경로 정보 계산                       |

### 3.3 구조도 해석 기준

```text
브라우저
  -> App Router 페이지
  -> 클라이언트 컴포넌트 / 상태 훅
  -> Route Handler
  -> Repository
  -> Supabase

브라우저
  -> Kakao Maps JS SDK / Daum Postcode

Route Handler
  -> Kakao Local API / Kakao Mobility API
```

## 4. 화면 구조 설계

### 4.1 public 화면 구조

public 화면은 다음으로 구성된다.

1. 랜딩 화면
2. 로그인 화면
3. 회원가입 화면
4. features 화면
5. about 화면

랜딩 화면은 서비스 소개와 로그인 진입 CTA 를 담당한다.
인증 화면은 로그인과 회원가입을 각각 독립 페이지로 제공한다.

### 4.2 보호 화면 구조

보호 화면은 다음으로 구성된다.

1. friends 허브 화면
2. chat 상세 화면

인증 세션이 없는 경우 보호 화면은 /login 으로 이동한다.

### 4.3 friends 허브 구조

friends 화면은 좌측 친구 목록 패널과 우측 허브 콘텐츠로 구성한다.

좌측 패널:

1. 친구 목록 제목
2. 친구 필터 입력
3. 친구 목록

우측 콘텐츠:

1. 친구 검색 및 요청 카드
2. 받은 요청 목록
3. 보낸 요청 목록
4. 친구 수 요약
5. 선택 친구 미리보기
6. 다음 단계 안내 영역

### 4.4 chat 상세 구조

chat 화면은 다음 블록을 포함한다.

1. 좌측 친구 목록 패널
2. 친구 헤더 카드
3. 채팅 패널
4. 위치 상태 패널
5. 추천 입력 패널
6. 추천 결과 패널
7. 추천 지도 패널
8. 저장 위치/주소 검색/핀 지정/지도 레이어

### 4.5 추천 지도 구조

추천 지도는 화면 크기에 따라 두 구조를 가진다.

1. 데스크톱: 지도 패널 + 전체화면 지도 오버레이
2. 모바일: 전체화면 지도 레이어 + 하단 시트 상태

모바일 지도 레이어는 collapsed, half, expanded 상태를 가지며, 하단 시트와 실제 지도 캔버스가 함께 가용 높이를 채우도록 설계한다.

## 5. 사용자 흐름 구조

### 5.1 기본 흐름

1. 사용자가 랜딩 화면에서 로그인 화면으로 이동한다.
2. 로그인 또는 회원가입 성공 후 /friends 로 이동한다.
3. users 는 friends 화면에서 친구를 검색하고 요청을 보낸다.
4. 친구 요청이 수락되면 친구 목록에서 선택 가능해진다.
5. 사용자는 /chat?friend={id} 로 이동해 상세 상호작용을 진행한다.
6. 메시지, 위치, 저장 위치, 추천 입력을 처리한다.
7. 추천 요청 후 결과 카드와 지도에서 후보를 확인한다.

### 5.2 채팅 흐름

1. 친구 선택
2. 메시지 조회
3. 메시지 입력
4. 전송
5. 읽음 포인터와 최신 메시지 상태 갱신

### 5.3 위치 및 추천 흐름

1. 현재 위치 공유 또는 later 모드 출발 위치 선택
2. 저장 위치 조회/선택/수정/삭제
3. 카테고리 선택
4. 추천 요청
5. 추천 카드, 지도 마커, 길찾기 카드 확인

### 5.4 모바일 흐름

1. 모바일에서도 동일한 추천 입력과 결과 흐름을 유지한다.
2. 좁은 화면에서는 헤더, 대화, 지도 패널이 접기/펼치기 상태를 가진다.
3. 추천 지도는 전체화면 레이어로 진입하고, 하단 시트 높이 조절로 정보와 지도를 전환한다.

## 6. 데이터 흐름 구조

### 6.1 인증 데이터 흐름

1. login/signup 화면에서 입력값을 수집한다.
2. auth Route Handler 에 요청을 보낸다.
3. 서버는 Supabase users 조회 또는 생성을 수행한다.
4. 성공 시 JWT 쿠키를 발급한다.
5. 이후 보호 페이지와 보호 API 는 해당 쿠키를 기준으로 동작한다.

### 6.2 친구 데이터 흐름

1. friends 화면 진입 시 친구 목록과 요청 상태를 조회한다.
2. 검색 요청은 nickname 기준으로 별도 조회한다.
3. 요청 생성/수락/거절/삭제 후 화면 상태를 다시 반영한다.

### 6.3 메시지 데이터 흐름

1. chat 화면은 friendId 기준으로 메시지를 조회한다.
2. 메시지 전송 시 sender 는 현재 로그인 사용자로 고정된다.
3. 읽음 시각과 마지막 메시지 포인터는 응답에 함께 포함된다.

### 6.4 위치와 저장 위치 데이터 흐름

1. 현재 위치는 users 의 lat/lng 와 공유 범위 컬럼으로 저장한다.
2. 저장 위치는 departure_locations 에 저장한다.
3. 저장 위치는 내 출발 위치와 친구 출발 위치를 같은 구조 안에서 관리한다.
4. 저장 위치 사용 시 last_used_at 을 갱신한다.

### 6.5 추천 데이터 흐름

1. 추천 요청은 friendId, mode, category, 필요 시 departure 정보를 포함한다.
2. 서버는 친구 관계와 위치 가시성을 검증한다.
3. service 계층이 중심점 계산, 후보 검색, 점수 정렬을 수행한다.
4. 응답은 카드와 지도 패널에서 동시에 사용된다.

---

## 7. 인증 구조 설계

1. JWT 쿠키 기반 세션을 사용한다.
2. 보호 페이지는 서버에서 세션을 확인해 리다이렉트한다.
3. 보호 API 는 createProtectedRoute 로 공통 검증을 수행한다.
4. 로그아웃은 쿠키 삭제만으로 처리한다.

---

## 8. 현재 구조 결론

1. MeetPoint 는 이미 public 페이지와 보호 앱 화면이 분리된 구조를 가진다.
2. 핵심 구조는 friends 허브와 chat 상세 흐름에 집중되어 있다.
3. 서버와 저장소 계층도 이미 구현되어 있어 현재 구조 설계는 실행 가능한 상태이다.
4. 이후 작업은 구조 신설보다 문서, QA, 세부 정책 정렬에 가깝다.

# MeetPoint 배포 및 환경설정 문서

## 1. 문서 목적

이 문서는 MeetPoint의 현재 구현을 local, preview, production 환경에 배포하고 운영할 때 필요한 기준을 정리한 문서이다.

현재 문서는 더 이상 퍼블리싱 UI 전용 배포 문서가 아니다. Next.js 16 App Router 앱, Route Handler 기반 API, Supabase 연동, Kakao 지도와 검색 연동, Vercel cron 헬스체크까지 포함한 실제 운영 기준을 다룬다.

## 4. Vercel 배포 기준

### 4.1 배포 플랫폼

기본 배포 플랫폼은 Vercel이다.

선정 이유:

1. Next.js 16 배포와 궁합이 가장 좋다.
2. 브랜치별 preview 생성이 쉽다.
3. GitHub 연동 자동 배포 흐름을 바로 사용할 수 있다.
4. vercel.json 기반 cron 설정을 함께 운영할 수 있다.

### 4.2 Vercel 프로젝트 필수 설정

1. Framework Preset: Next.js
2. Root Directory: 01_sungeun15
3. Install Command: pnpm install
4. Build Command: pnpm build
5. Start Command: 기본 Next.js 동작 사용

주의:

1. 워크스페이스 루트를 Root Directory 로 잡지 않는다.
2. .my_work 폴더를 배포 루트로 잡지 않는다.
3. pnpm-lock.yaml 기준으로 pnpm 을 사용한다.

### 4.3 자동 배포 방식

1. GitHub 저장소를 Vercel 프로젝트에 연결한다.
2. 브랜치 push 시 preview 배포가 생성된다.
3. main 반영 시 production 배포가 갱신된다.

## 5. 환경 변수 기준

### 5.1 필수 변수

현재 구현 기준으로 아래 값들이 필요하다.

| 변수명                               | 용도                                     | 노출 범위      |
| ------------------------------------ | ---------------------------------------- | -------------- |
| NEXT_PUBLIC_SUPABASE_URL             | Supabase 프로젝트 URL                    | 브라우저, 서버 |
| NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY | 공개용 Supabase 키                       | 브라우저, 서버 |
| SUPABASE_SERVICE_ROLE_KEY            | 서버 전용 관리자 키                      | 서버 전용      |
| SUPABASE_DATABASE_URL                | DB 테스트 및 점검 스크립트용 연결 문자열 | 서버 전용      |
| JWT_SECRET                           | JWT 서명 및 검증                         | 서버 전용      |
| NEXT_PUBLIC_KAKAO_MAP_APP_KEY        | Kakao Map JavaScript SDK 로드            | 브라우저       |
| KAKAO_LOCAL_REST_API_KEY             | Kakao Local API 호출                     | 서버 전용      |
| CRON_SECRET                          | /api/health/supabase 인증                | 서버 전용      |

### 5.2 공개 변수와 비공개 변수 구분

원칙은 단순하다.

1. NEXT_PUBLIC_ 접두사가 있으면 브라우저에 노출 가능하다.
2. NEXT_PUBLIC_ 접두사가 없으면 서버 전용이다.

반드시 지킬 항목:

1. SUPABASE_SERVICE_ROLE_KEY 를 공개 변수로 넣지 않는다.
2. JWT_SECRET 을 공개 변수로 넣지 않는다.
3. KAKAO_LOCAL_REST_API_KEY 를 클라이언트 코드에서 직접 쓰지 않는다.
4. CRON_SECRET 을 문서나 저장소에 실제 값으로 남기지 않는다.

### 5.3 예시

```env
NEXT_PUBLIC_SUPABASE_URL=https://sample-project.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_sample-key-value
SUPABASE_SERVICE_ROLE_KEY=sample-service-role-key-value
SUPABASE_DATABASE_URL=postgresql://postgres.your-project-ref:[YOUR_PASSWORD]@aws-0-your-region.pooler.supabase.com:5432/postgres
JWT_SECRET=meetpoint-local-jwt-secret-2026-example
NEXT_PUBLIC_KAKAO_MAP_APP_KEY=1234567890abcdef1234567890abcdef
KAKAO_LOCAL_REST_API_KEY=abcdef1234567890abcdef1234567890
CRON_SECRET=sample-cron-secret
```

### 5.4 환경별 관리 원칙

1. local, preview, production 값을 분리한다.
2. preview 는 production 과 동일한 구조의 값을 유지한다.
3. 실제 비밀 값은 저장소에 커밋하지 않는다.
4. DB 관리자 권한 값과 앱 실행 최소값을 혼합하지 않는다.

## 6. 환경별 운영 기준

### 6.1 local

로컬 개발 기본 명령:

```bash
pnpm dev
```

production 유사 점검:

```bash
pnpm build
pnpm start
```

local 에서 먼저 확인할 항목:

1. 로그인, 회원가입, friends, chat 진입
2. Kakao 지도 로드
3. Daum Postcode 레이어 오픈
4. 추천 결과 목록과 지도 동기화
5. 모바일 전체화면 지도 동작

### 6.2 preview

preview 는 로컬 명령이 아니라 Vercel 이 생성하는 원격 검토 환경이다.

주요 용도:

1. 브랜치 결과 공유
2. QA 시나리오 검토
3. production 반영 전 환경 변수 문제 분리

preview 에서는 아래를 우선 본다.

1. 로그인 가능 여부
2. 보호 페이지 이동 규칙
3. Kakao 지도와 검색 연동
4. 추천 응답과 길찾기 카드
5. 모바일 지도 레이아웃 붕괴 여부

### 6.3 production

production 은 실제 운영 주소에서 동작하는 환경이다.

운영 시 특히 엄격하게 볼 항목:

1. 비공개 환경 변수 누락 여부
2. Supabase 연결 이상 여부
3. cron 헬스체크 성공 여부
4. 빌드 후 치명적 서버 오류 여부

## 7. 헬스체크와 cron 운영

### 7.1 vercel.json 기준

현재 vercel.json 에는 아래 cron 이 설정되어 있다.

1. 경로: /api/health/supabase
2. 스케줄: 매일 03:00 UTC 기준 1회

### 7.2 API 동작 기준

GET /api/health/supabase 는 아래 조건을 만족해야 성공한다.

1. CRON_SECRET 이 설정되어 있어야 한다.
2. Authorization 헤더가 Bearer CRON_SECRET 형식이어야 한다.
3. Supabase 필수 테이블 헬스체크가 모두 reachable 이어야 한다.

실패 조건:

1. CRON_SECRET 미설정 시 503
2. Authorization 불일치 시 403
3. 테이블 접근 실패 시 503

### 7.3 운영 점검 방법

1. Vercel cron 실행 로그 확인
2. Route Handler 응답 코드 확인
3. Supabase 테이블 접근 실패 시 실패 테이블 목록 확인

## 11. 자주 발생하는 문제와 대응

### 11.1 빌드 실패

주요 원인:

1. Root Directory 오설정
2. pnpm 대신 다른 패키지 매니저 사용
3. 타입 오류 또는 import 오류

확인 순서:

1. Root Directory 재확인
2. local 에서 pnpm build 재현
3. lint 와 type-check 결과 확인

### 11.2 로그인 또는 API 500 오류

주요 원인:

1. Supabase URL 또는 키 누락
2. JWT_SECRET 누락
3. service role key 누락

확인 순서:

1. preview 와 production 환경 변수 비교
2. 서버 로그 확인
3. /api/health/supabase 결과 확인

### 11.3 지도는 뜨지만 검색 또는 추천이 실패하는 경우

주요 원인:

1. KAKAO_LOCAL_REST_API_KEY 누락
2. 출발 위치 데이터 부족
3. Kakao 도메인 등록 불일치

확인 순서:

1. 지도 SDK 와 장소 검색 문제를 분리해서 본다.
2. search 와 pin 지정이 각각 되는지 확인한다.
3. 추천 요청 payload 와 응답을 확인한다.

### 11.4 cron 헬스체크 실패

주요 원인:

1. CRON_SECRET 누락
2. Authorization 헤더 불일치
3. Supabase 필수 테이블 접근 실패

확인 순서:

1. CRON_SECRET 등록 확인
2. Vercel cron 실행 로그 확인
3. 실패 응답의 테이블 목록 확인

---

## 12. 운영 원칙

1. preview 확인 없이 production 반영하지 않는다.
2. 실제 비밀 값은 문서, 채팅, 커밋에 남기지 않는다.
3. 코드 문제와 환경 변수 문제를 분리해서 본다.
4. 배포 실패 시 local build 재현부터 확인한다.
5. cron 장애는 Supabase 접속 장애와 함께 본다.

---

## 13. 최종 정리

현재 MeetPoint 배포 기준은 아래처럼 요약할 수 있다.

1. Vercel 에 01_sungeun15 앱을 Root Directory 로 배포한다.
2. Supabase, JWT, Kakao, CRON_SECRET 환경 변수를 환경별로 분리 관리한다.
3. preview 에서 인증, 친구, 채팅, 추천, 모바일 지도 흐름을 확인한 뒤 production 으로 반영한다.
4. 배포 후에는 /api/health/supabase 와 Vercel cron 상태까지 함께 본다.

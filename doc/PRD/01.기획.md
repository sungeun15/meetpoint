# MeetPoint 기획안

## 1. 프로젝트 개요

### 1.1 프로젝트명

MeetPoint

### 1.2 한 줄 소개

MeetPoint 는 친구와 댓글형 채팅을 주고받고, 현재 위치 또는 선택한 출발 위치를 기준으로 공정한 약속 장소를 추천해 주는 웹 서비스이다.

### 1.3 프로젝트 배경

약속 장소를 정할 때 사용자는 메신저, 지도 앱, 장소 검색 서비스를 여러 번 오가야 한다. 이 과정은 번거롭고, 서로 다른 위치에 있는 두 사람이 공정한 약속 장소를 빠르게 정하기 어렵다.

또한 실제 약속은 항상 현재 위치에서 출발하지 않으며, 단순한 중간 지점만으로는 만족도 높은 장소를 추천하기 어렵다. MeetPoint 는 이 문제를 해결하기 위해 채팅, 위치, 출발 위치 선택, 추천을 하나의 흐름으로 연결한다.

---

## 2. 문제 정의

MeetPoint 가 해결하려는 불편은 다음과 같다.

1. 대화 공간과 장소 탐색 공간이 분리되어 있다.
2. 두 사람 모두에게 공정한 장소를 빠르게 찾기 어렵다.
3. 현재 위치와 실제 출발 위치가 다를 수 있어 추천 기준이 왜곡된다.
4. 카페, 식사, 놀거리처럼 만남 목적이 달라도 동일한 추천 기준이 적용된다.
5. 추천 결과가 지도와 거리 정보로 함께 제시되지 않으면 판단이 어렵다.
6. 여러 앱을 오가며 정보를 조합해야 하므로 흐름이 끊긴다.

---

## 3. 프로젝트 목표

### 3.1 서비스 목표

1. 친구와 약속 장소를 정하는 과정을 한 화면 흐름으로 단순화한다.
2. 지금 만나기와 나중에 만나기 두 상황을 모두 지원한다.
3. 공정성과 실제 이용 가능성을 함께 고려한 추천 경험을 제공한다.
4. 모바일과 데스크톱 모두에서 자연스럽게 동작하는 MVP 를 완성한다.

### 3.2 개발 목표

1. Next.js 16 기반 풀스택 구조로 프론트엔드와 백엔드를 통합한다.
2. Supabase 와 Kakao 계열 API 를 활용해 MVP 속도와 구현 안정성을 확보한다.
3. Route Handler, repository, service 구조로 이후 확장을 준비한다.
4. 문서와 실제 구현 상태를 계속 맞춰 유지한다.

---

## 4. 핵심 가치 제안

1. 통합성: 채팅, 위치, 저장 위치, 추천을 한 서비스 안에서 처리한다.
2. 공정성: 한 사람에게만 유리한 장소가 아니라 두 사람 모두에게 적절한 장소를 제안한다.
3. 유연성: 현재 위치 기반 번개 약속과 미래 출발 위치 기반 약속을 모두 지원한다.
4. 명확성: 추천 기준과 입력 흐름이 화면 안에서 이해 가능하도록 제시된다.
5. 실용성: 추천 카드, 지도, 길찾기 보조 정보를 함께 제공해 바로 결정할 수 있다.

---

## 5. 대상 사용자

### 5.1 주요 사용자

1. 친구와 약속 장소를 자주 정하는 대학생과 사회 초년생
2. 서로 다른 지역에서 만나야 하는 사용자
3. 복잡한 절차 없이 빠르게 약속 장소를 정하고 싶은 사용자

### 5.2 사용 상황

1. 수업 후 바로 만날 장소를 정해야 하는 번개 약속
2. 며칠 뒤 약속을 위해 각자 출발 위치를 미리 정하고 장소를 고르는 상황
3. 카페, 식사, 놀거리 등 목적에 맞는 약속 장소를 찾는 상황
4. 대화와 장소 결정을 같은 흐름 안에서 끝내고 싶은 상황

## 6. 핵심 사용자 시나리오

1. 사용자는 랜딩 화면에서 서비스 소개와 로그인 진입 CTA 를 확인한다.
2. 사용자는 로그인 또는 회원가입을 완료한다.
3. 인증 이후 사용자는 friends 허브에서 친구를 검색하고 요청을 보낸다.
4. 친구 요청이 수락되면 친구 목록에서 해당 친구를 선택한다.
5. 사용자는 chat 상세 화면에서 친구 정보, 댓글형 채팅, 위치 상태를 확인한다.
6. 사용자는 지금 만나기 또는 나중에 만나기 모드를 선택한다.
7. 지금 만나기에서는 현재 위치를 공유하고, 나중에 만나기에서는 내 출발 위치와 친구 출발 위치를 각각 주소 검색, 핀 지정, 저장 위치 선택으로 정한다.
8. 필요하면 위치를 저장 위치 목록에 추가하거나 기존 저장 위치를 수정/삭제한다.
9. 사용자는 카페, 식사, 놀거리 중 하나의 카테고리를 선택해 추천을 요청한다.
10. 추천 결과 요약, 장소 카드, 지도, 길찾기 보조 정보를 보고 약속 장소를 결정한다.

## 8. MVP 구현 확정안

### 8.1 사용자 식별 방식

1. 닉네임 + 비밀번호 기반 회원가입과 로그인 방식을 사용한다.
2. 서버는 JWT 를 발급하고 httpOnly 쿠키에 저장한다.
3. 보호 페이지와 보호 API 는 해당 쿠키를 기준으로 현재 사용자를 식별한다.

### 8.2 친구 관계 방식

1. 친구 추가는 즉시 등록이 아니라 요청 생성 방식으로 처리한다.
2. 요청 상태는 pending 과 accepted 를 가진다.
3. 수락 후에는 양방향 친구 관계를 유지한다.

### 8.3 추천 결과 처리 방식

1. 추천 결과는 요청 시마다 계산 후 반환한다.
2. MVP 단계에서는 별도 추천 이력 테이블에 저장하지 않는다.

### 8.4 추천 입력 기준

1. 지금 만나기 모드에서는 현재 공유 위치를 사용한다.
2. 나중에 만나기 모드에서는 사용자가 지정한 출발 위치를 사용한다.
3. 추천 요청 시 카테고리를 함께 전달한다.

### 8.5 지도 및 길찾기 방식

1. Kakao Maps JS SDK 로 지도와 마커를 표시한다.
2. Kakao Local API 로 장소 후보를 조회한다.
3. Kakao Mobility API 또는 fallback 계산으로 길찾기 보조 정보를 제공한다.

## 9. 기능 상세 기획

### 9.1 친구 기능

1. 닉네임으로 사용자를 검색한다.
2. 친구 요청을 보낸다.
3. 받은 요청을 수락 또는 거절한다.
4. 수락된 친구만 채팅과 추천 대상이 된다.
5. 필요 시 채팅방 나가기로 친구 관계를 종료할 수 있다.

### 9.2 채팅 기능

1. 채팅은 댓글형 메시지 UI 로 제공한다.
2. 사용자는 메시지를 입력하고 전송할 수 있다.
3. 친구별로 채팅 화면이 전환된다.
4. 모바일에서는 대화 패널 접기 상태를 제공한다.

### 9.3 위치 공유 및 출발 위치 선택

1. 지금 만나기 모드에서는 현재 위치를 공유한다.
2. 위치 공유 범위는 특정 친구 또는 전체 친구 기준으로 선택한다.
3. 나중에 만나기 모드에서는 주소 검색, 핀 지정, 저장 위치 선택으로 출발 위치를 정한다.
4. 저장 위치는 내 출발 위치와 친구 출발 위치용으로 나누어 관리한다.

### 9.4 지도 표시

1. 추천 전에는 안내 상태를 보여 준다.
2. 추천 후에는 사용자 위치, 친구 위치, 중심점, 추천 장소를 함께 지도에 표시한다.
3. 모바일에서는 전체화면 지도와 하단 시트를 통해 좁은 화면에서도 지도를 크게 볼 수 있어야 한다.

### 9.5 추천 기능

1. 중심점은 두 출발 좌표 기준으로 계산한다.
2. 중심점 주변 후보 장소를 검색한다.
3. 평균 거리, 거리 편차, 카테고리 적합도, 활성도 기준을 조합해 점수를 계산한다.
4. 상위 10개 장소를 결과로 반환한다.

## 11. 현재 기획 결론

1. MeetPoint 의 현재 MVP 는 단순 화면 시안 단계가 아니라 인증, 친구 요청, 채팅, 위치, 추천까지 연결된 실행 가능한 구조를 갖는다.
2. 핵심 제품 가치는 친구와의 대화 흐름 안에서 공정한 약속 장소를 빠르게 정하게 해 주는 데 있다.
3. 남은 작업은 새로운 기획 확장보다 현재 구현의 완성도와 문서 정합성을 높이는 데 우선순위를 둔다.

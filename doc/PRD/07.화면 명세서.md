# MeetPoint 화면 명세서

## 1\. 문서 목적

이 문서는 MeetPoint MVP 1차 구현에 필요한 화면 구성을 고정하기 위한 문서이다.

기획 문서, 기술 설계 문서, API 명세서에서 정의한 기능을 실제 사용자 화면 기준으로 다시 정리하여, 어떤 화면이 필요하고 각 화면에서 무엇을 보여 주며 어떤 행동을 처리해야 하는지를 한 번에 이해할 수 있도록 만드는 것을 목표로 한다.

---

## 2\. 범위

본 문서는 아래 항목을 포함한다.

1.  시작 화면
2.  메인 화면
3.  친구 선택 후 상세 사용 화면
4.  지도 및 추천 결과 노출 방식
5.  빈 상태, 오류 상태, 로딩 상태
6.  화면 간 이동 흐름

본 문서의 기본 범위에서 제외하는 항목은 아래와 같다.

1.  실시간 소켓 UI 세부 설계
2.  비밀번호 재설정 화면
3.  닉네임 찾기 화면
4.  관리자 화면
5.  추천 이력 전용 화면

---

## 3\. 화면 설계 기준

### 3.1 기준 시안

현재 화면 명세는 전달받은 간단한 피그마 시안을 기준으로 정리한다.

아래 이미지는 이번 화면 명세에서 참고하는 시안들이다.

#### 시안 A. 서비스 첫 인상 화면

![MeetPoint 서비스 첫 인상 시안](../image/frame1.png)

이 시안은 실제 기능 화면이라기보다 서비스의 첫 인상과 랜딩 톤을 보여 주는 참고 이미지이다.

상단 헤더, 브랜드 로고, 핵심 소개 문구, 시작 CTA가 어떤 분위기로 배치되는지를 확인하는 용도로 사용한다.

#### 시안 B. 시작 화면 입력 카드

![MeetPoint 시작 화면 시안](../image/frame2.png)

이 시안은 사용자가 실제로 처음 상호작용하는 시작 화면 구조를 보여 준다.

중앙 인증 카드, 입력 필드, 진행 버튼의 배치를 확인하는 기준 화면으로 본다.

#### 시안 C. 메인 기본 화면

![MeetPoint 메인 기본 화면 시안](../image/frame3.png)

이 시안은 로그인 이후 메인 화면의 기본 레이아웃을 보여 준다.

좌측 친구 목록과 우측 메인 패널이 어떻게 분리되는지, 친구 추가 카드와 지도 안내 카드가 어떤 위치 관계를 가지는지 확인하는 기준으로 사용한다.

#### 시안 D. 친구 선택 상세 화면

![MeetPoint 친구 선택 상세 화면 시안](../image/frame4.png)

이 시안은 친구를 선택한 뒤 채팅 중심 상태로 전환된 대표 예시 화면을 보여 준다.

좌측 친구 목록 유지, 우측 채팅 패널 확장, 지도 확인 액션 연결 구조를 확인하는 참고 시안으로 사용한다.

시안에서 확인되는 핵심은 아래 두 장면이다.

1.  중앙 카드형 시작 화면
2.  좌측 친구 목록 + 우측 메인 콘텐츠 구조의 메인 화면

즉, 본 문서는 시안의 배치 방향은 유지하되, MVP 요구사항에 맞게 실제 구현에 필요한 입력 요소와 상태를 더해 명세를 확정한다.

### 3.2 시안과 실제 구현 명세의 차이

피그마 시안은 화면 분위기와 레이아웃 방향을 빠르게 잡기 위한 간단한 버전이다.

따라서 실제 구현 명세에서는 아래 항목을 추가로 반영해야 한다.

1.  시작 화면에 닉네임뿐 아니라 비밀번호 입력이 필요하다.
2.  시작 화면에는 회원가입과 로그인 액션이 분리되어야 한다.
3.  메인 화면에서는 친구 추가, 친구 선택, 채팅, 위치 공유, 추천 결과 표시 흐름이 모두 연결되어야 한다.
4.  추천 결과는 카드 목록과 지도 마커 두 방식으로 동시에 보여야 한다.

### 3.3 공통 UI 방향

1.  상단에는 단순한 공통 헤더를 둔다.
2.  본문은 카드형 구획과 명확한 섹션 분리로 구성한다.
3.  MVP 발표 시연 기준으로 한 화면에서 핵심 흐름이 바로 보이도록 한다.
4.  데이터가 없는 상태와 오류 상태를 숨기지 않고 분명하게 보여 준다.

## 4\. 전체 화면 목록

| 화면 ID | 화면명              | 경로  | 인증 필요 | 설명                                                        |
| ------- | ------------------- | ----- | --------- | ----------------------------------------------------------- |
| SCR-01  | 시작 화면           | /     | 아니오    | 회원가입 또는 로그인 진입 화면                              |
| SCR-02  | 메인 기본 화면      | /main | 예        | 친구 목록, 친구 추가, 지도 진입, 기본 안내를 보여 주는 화면 |
| SCR-03  | 친구 선택 상세 화면 | /main | 예        | 선택한 친구 기준 채팅, 위치, 추천 기능을 함께 사용하는 화면 |
| SCR-04  | 추천 결과 강조 상태 | /main | 예        | 추천 요청 후 중심점과 추천 장소 3개를 강조 표시한 상태      |

중요한 점은 SCR-02, SCR-03, SCR-04가 완전히 다른 페이지라기보다, 메인 페이지 내부 상태 변화로 동작할 수 있다는 점이다.

즉, MVP 기준 실제 라우팅은 시작 화면과 메인 화면 두 개를 기본으로 두고, 메인 화면 내부 상태가 확장되는 구조로 이해하면 된다.

## 5\. 공통 레이아웃 명세

### 5.1 공통 헤더

모든 주요 화면 상단에는 공통 헤더를 둔다.

구성 요소는 아래와 같다.

1.  서비스 로고 또는 meetpoint 텍스트
2.  단순 네비게이션 텍스트 영역
3.  우측 사용자 액션 버튼

시안 기준으로 Home, Features, About us 같은 메뉴가 보이지만, MVP 구현에서는 아래 기준으로 단순화할 수 있다.

1.  로고
2.  서비스 소개용 링크 또는 비활성 메뉴
3.  로그인 상태 표시 또는 로그아웃 버튼

### 5.2 본문 레이아웃

1.  시작 화면은 중앙 카드 정렬 구조를 사용한다.
2.  메인 화면은 좌측 사이드 패널 + 우측 메인 패널 구조를 사용한다.
3.  우측 메인 패널은 친구 추가 영역, 지도/추천 영역, 채팅/상세 영역으로 확장 가능해야 한다.

## 6\. SCR-01 시작 화면 명세

### 6.1 화면 목적

사용자가 서비스에 처음 진입했을 때 회원가입 또는 로그인을 진행하는 화면이다.

#### 참고 시안

![SCR-01 시작 화면 참고 시안](../image/frame2.png)

위 시안은 SCR-01의 기본 골격을 설명하는 참고 이미지이다.

현재 시안에는 닉네임 입력과 단일 진행 버튼만 보이지만, 실제 구현에서는 아래 명세처럼 비밀번호 입력과 회원가입, 로그인 액션을 함께 포함해야 한다.

### 6.2 화면 구성

시안 기준 핵심 구성은 아래와 같다.

1.  중앙 카드
2.  서비스 환영 문구
3.  입력 필드
4.  주요 진행 버튼

실제 MVP 구현 명세에서는 아래 요소로 확장한다.

1.  서비스 로고 또는 아이콘
2.  Welcome to MeetPoint 제목
3.  서비스 설명 문구
4.  닉네임 입력 필드
5.  비밀번호 입력 필드
6.  회원가입 버튼
7.  로그인 버튼
8.  검증 오류 문구 영역

### 6.3 표시 데이터

| 항목          | 형식           | 설명                         |
| ------------- | -------------- | ---------------------------- |
| nickname      | text input     | 사용자가 입력하는 닉네임     |
| password      | password input | 사용자가 입력하는 비밀번호   |
| error message | text           | 검증 실패 또는 API 실패 안내 |

### 6.4 사용자 액션

| 액션          | 설명                 | 결과                                |
| ------------- | -------------------- | ----------------------------------- |
| 닉네임 입력   | 닉네임 입력값 작성   | 내부 상태 갱신                      |
| 비밀번호 입력 | 비밀번호 입력값 작성 | 내부 상태 갱신                      |
| 회원가입 클릭 | 회원가입 요청        | 성공 시 JWT 쿠키 발급 후 /main 이동 |
| 로그인 클릭   | 로그인 요청          | 성공 시 JWT 쿠키 발급 후 /main 이동 |

### 6.5 검증 규칙

1.  닉네임은 정규화 후 2자 이상 12자 이하만 허용한다.
2.  닉네임은 한글, 영문, 숫자, 공백만 허용한다.
3.  비밀번호는 8자 이상 20자 이하만 허용한다.
4.  검증 실패 시 입력 카드 내부에 오류 문구를 표시한다.

### 6.6 상태 정의

#### 기본 상태

빈 입력 상태에서 사용자를 기다린다.

#### 입력 중 상태

사용자가 닉네임과 비밀번호를 입력 중인 상태이다.

#### 요청 중 상태

회원가입 또는 로그인 버튼 클릭 후 API 응답을 기다리는 상태이다.

이때 버튼은 중복 클릭을 막기 위해 비활성화할 수 있다.

#### 오류 상태

1.  닉네임 형식 오류
2.  비밀번호 길이 오류
3.  중복 닉네임
4.  로그인 실패
5.  서버 오류

### 6.7 화면 메모

피그마 시안에는 닉네임 입력과 Continue 버튼만 보이지만, 실제 구현은 인증 요구사항에 맞게 닉네임과 비밀번호, 회원가입과 로그인 액션을 모두 포함해야 한다.

## 7\. SCR-02 메인 기본 화면 명세

### 7.1 화면 목적

로그인 이후 사용자가 친구 목록을 보고, 친구를 추가하고, 위치 공유와 지도 확인, 추천 기능으로 들어가기 위한 기본 허브 화면이다.

#### 참고 시안

![SCR-02 메인 기본 화면 참고 시안](../image/frame3.png)

위 시안은 친구를 아직 선택하지 않은 메인 기본 상태를 설명하는 참고 이미지이다.

좌측 친구 목록, 우측 친구 추가 영역, 지도 진입 카드가 한 화면 안에서 어떻게 배치되는지 확인할 수 있다.

### 7.2 전체 구조

시안 기준으로 화면은 크게 두 영역으로 나뉜다.

1.  좌측 친구 패널
2.  우측 메인 콘텐츠 패널

### 7.3 좌측 친구 패널 구성

구성 요소는 아래와 같다.

1.  친구 목록 제목
2.  친구 검색 또는 필터 입력창
3.  친구 목록 카드 반복

각 친구 카드에는 아래 정보가 들어간다.

1.  프로필 플레이스홀더 또는 아바타
2.  친구 닉네임
3.  선택 이동 아이콘 또는 화살표

### 7.4 우측 메인 콘텐츠 기본 구성

시안 기준 기본 콘텐츠는 아래 두 블록으로 보인다.

1.  친구 추가 카드
2.  지도 보기 안내 카드

실제 MVP 명세에서는 아래 요소를 포함한다.

1.  친구 추가 입력 필드
2.  친구 추가 버튼 또는 검색 버튼
3.  선택된 친구가 없을 때의 안내 문구
4.  지도 보기 CTA 카드
5.  추천 기능 진입 전 안내 영역

### 7.5 표시 데이터

| 항목                  | 형식       | 설명                                              |
| --------------------- | ---------- | ------------------------------------------------- |
| currentUserNickname   | text       | 우측 상단 또는 헤더에 표시하는 현재 사용자 닉네임 |
| friends\[\]           | list       | 현재 사용자 친구 목록                             |
| friend search keyword | text input | 친구 필터 또는 검색 키워드                        |
| add friend keyword    | text input | 친구 추가용 닉네임 입력                           |

### 7.6 사용자 액션

| 액션                     | 설명                | 결과                               |
| ------------------------ | ------------------- | ---------------------------------- |
| 친구 검색 입력           | 친구 목록 필터      | 목록 필터링                        |
| 친구 추가 입력           | 새 친구 닉네임 입력 | POST /api/friends 준비             |
| 검색 또는 추가 버튼 클릭 | 친구 추가 요청      | 성공 시 목록 갱신                  |
| 친구 카드 클릭           | 친구 선택           | SCR-03 상태로 전환                 |
| 지도 보기 클릭           | 지도 중심 UI 노출   | 지도 카드 강조 또는 상세 패널 이동 |

### 7.7 상태 정의

#### 기본 상태

친구 목록과 친구 추가 카드가 보이지만 아직 특정 친구는 선택되지 않은 상태이다.

#### 친구 없음 상태

친구 목록이 비어 있으면 빈 상태 문구를 보여 준다.

예시:

1.  아직 추가된 친구가 없습니다.
2.  닉네임으로 친구를 검색해 추가해 보세요.

#### 친구 추가 실패 상태

아래 오류를 보여 줄 수 있다.

1.  존재하지 않는 닉네임
2.  자기 자신 추가 시도
3.  이미 추가된 친구
4.  서버 오류

## 8\. SCR-03 친구 선택 상세 화면 명세

### 8.1 화면 목적

특정 친구를 선택한 뒤 채팅, 위치 확인, 추천 요청까지 이어지는 핵심 사용 화면이다.

#### 참고 시안

![SCR-03 친구 선택 상세 화면 참고 시안](../image/frame4.png)

위 시안은 특정 친구를 선택한 직후 나타나는 채팅 중심 대표 상태를 설명하는 참고 이미지이다.

친구 선택 강조, 채팅 패널 활성화, 지도 확인 액션 노출이 동시에 일어나는 구조를 이해하는 데 사용한다. 다만 위치 상태 영역, 지도 카드, 추천 결과 전체를 모두 보여 주는 완성 화면은 아니므로 SCR-03의 대표 상태 예시로 해석한다.

### 8.2 구성 영역

친구를 선택하면 메인 화면 우측 콘텐츠 영역은 아래 블록을 포함해야 한다.

1.  선택한 친구 정보 영역
2.  채팅 패널
3.  위치 상태 영역
4.  지도 카드
5.  추천 버튼 또는 추천 결과 영역

### 8.3 선택한 친구 정보 영역

표시 항목은 아래와 같다.

1.  친구 닉네임
2.  마지막 위치 공유 시각 요약
3.  현재 추천 기준 대상인지 여부

### 8.4 채팅 패널

채팅 패널은 아래 구조를 가진다.

1.  메시지 목록
2.  메시지 입력창
3.  전송 버튼

메시지는 댓글형 저장 방식이며, 최신 대화 흐름을 시간순으로 보여 준다.

### 8.5 위치 상태 영역

구성 요소는 아래와 같다.

1.  내 위치 상태 문구
2.  친구 위치 상태 문구
3.  마지막 위치 공유 시각
4.  위치 공유 버튼

위치 공유 버튼 클릭 시 현재 브라우저 위치 권한 요청 후 POST /api/location 흐름이 이어진다.

### 8.6 지도 카드

지도 카드에는 아래 정보를 표시한다.

1.  내 위치 마커
2.  친구 위치 마커
3.  친구 선택 전에는 기본 안내 또는 기본 중심 좌표
4.  추천 요청 후에는 중심점 및 추천 장소 마커 추가

### 8.7 사용자 액션

| 액션           | 설명                | 결과                  |
| -------------- | ------------------- | --------------------- |
| 메시지 입력    | 댓글 내용 입력      | 내부 상태 갱신        |
| 전송 클릭      | 메시지 저장 요청    | 목록 갱신             |
| 위치 공유 클릭 | 현재 위치 저장 요청 | 지도와 상태 문구 갱신 |
| 추천 클릭      | 추천 결과 요청      | SCR-04 상태로 확장    |

### 8.8 빈 상태

#### 친구는 선택했지만 메시지가 없는 경우

1.  아직 주고받은 메시지가 없습니다.
2.  첫 메시지를 보내 대화를 시작해 보세요.

#### 내 위치 또는 친구 위치가 없는 경우

1.  위치 공유 후 추천을 시작할 수 있습니다.
2.  두 사람 모두 위치가 있어야 추천 정확도가 올라갑니다.

## 9\. SCR-04 추천 결과 강조 상태 명세

### 9.1 화면 목적

두 사람의 위치를 기준으로 중간 지점과 추천 장소 3개를 시각적으로 확인하고, 약속 장소를 비교하는 상태이다.

### 9.2 표시 항목

| 항목        | 형식        | 설명                     |
| ----------- | ----------- | ------------------------ |
| midpoint    | object      | 계산된 중심 좌표         |
| places\[\]  | card list   | 추천 장소 3개 목록       |
| map markers | map overlay | 중심점 및 추천 장소 마커 |

### 9.3 추천 결과 카드 구성

각 추천 카드는 아래 정보를 포함한다.

1.  장소명
2.  카테고리
3.  사용자 A와의 거리
4.  사용자 B와의 거리
5.  평균 이동 거리 또는 점수 요약
6.  추천 우선순위

### 9.4 지도 표시 규칙

추천이 완료되면 지도에는 아래 마커를 함께 표시한다.

1.  현재 사용자 위치
2.  친구 위치
3.  중심점
4.  추천 장소 마커 3개

### 9.5 사용자 액션

| 액션           | 설명           | 결과                          |
| -------------- | -------------- | ----------------------------- |
| 추천 다시 요청 | 추천 재실행    | places 갱신                   |
| 추천 카드 선택 | 특정 장소 강조 | 지도 중심 이동 또는 강조 표시 |
| 친구 변경      | 다른 친구 선택 | SCR-03 상태 재초기화          |

### 9.6 빈 결과 상태

추천 후보가 없으면 아래 안내를 보여 준다.

1.  추천 가능한 장소를 찾지 못했습니다.
2.  위치를 다시 공유하거나 다른 친구를 선택해 보세요.

## 10\. 화면 간 이동 흐름

### 10.1 기본 사용자 흐름

```
시작 화면
    -> 회원가입 또는 로그인 성공
    -> 메인 기본 화면
    -> 친구 선택
    -> 친구 선택 상세 화면
    -> 위치 공유
    -> 추천 요청
    -> 추천 결과 강조 상태
```

### 10.2 보호 페이지 이동 규칙

1.  JWT 쿠키가 없으면 /main 진입 시 / 로 이동한다.
2.  JWT가 유효하면 /main 진입이 가능하다.
3.  로그아웃 시 시작 화면으로 되돌아간다.

## 11\. 공통 상태 명세

### 11.1 로딩 상태

아래 작업은 로딩 상태 표시가 필요하다.

1.  회원가입
2.  로그인
3.  친구 추가
4.  친구 목록 초기 조회
5.  메시지 조회
6.  메시지 전송
7.  위치 저장
8.  추천 결과 조회

### 11.2 오류 상태

오류는 가능한 한 사용자 행동 위치에 가까운 곳에서 보여 준다.

예시:

1.  인증 오류는 시작 화면 카드 내부
2.  친구 추가 오류는 친구 추가 카드 내부
3.  메시지 전송 오류는 채팅 패널 하단
4.  추천 오류는 추천 버튼 또는 추천 결과 영역 근처

### 11.3 빈 상태

빈 상태는 아래를 포함한다.

1.  친구 없음
2.  메시지 없음
3.  추천 결과 없음
4.  위치 없음
5.  친구 미선택

## 12\. 반응형 및 레이아웃 원칙

MVP 기준 기본 설계는 데스크톱 우선이지만, 최소한 아래 원칙은 지켜야 한다.

1.  좁은 화면에서는 좌측 친구 패널이 상단 또는 접이식 영역으로 재배치될 수 있어야 한다.
2.  지도, 채팅, 추천 카드가 겹쳐서 읽기 어렵지 않아야 한다.
3.  버튼과 입력창은 모바일에서도 누르기 가능한 크기를 유지해야 한다.

단, 발표 시연 우선순위상 데스크톱 기준 화면 완성도를 먼저 확보한다.

## 15\. 화면 명세 확정 기준

이 문서 기준 화면 설계가 충족되었다고 보려면 아래 조건을 만족해야 한다.

1.  시작 화면에서 회원가입과 로그인 흐름이 분리되어 있어야 한다.
2.  메인 화면에서 친구 목록, 친구 추가, 채팅, 위치, 추천 흐름이 한 구조 안에서 이어져야 한다.
3.  추천 결과는 카드와 지도 두 방식으로 모두 확인 가능해야 한다.
4.  친구 미선택, 데이터 없음, 오류 발생 같은 상태를 화면에서 구분할 수 있어야 한다.
5.  피그마 시안의 톤은 유지하되, MVP 요구사항에 필요한 요소 누락이 없어야 한다.

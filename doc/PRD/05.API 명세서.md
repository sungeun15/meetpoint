# MeetPoint API 명세서

## 1. 문서 목적

이 문서는 MeetPoint의 현재 서버 API 계약과 UI 연동 기준을 고정하기 위한 문서이다.

현재 구현에는 인증, 친구 요청, 채팅 메시지, 위치 공유, 저장 위치, 추천 조회, 추천 길찾기 보조 API 가 이미 포함되어 있으므로, 본 문서는 실제 Route Handler 기준의 요청, 응답, 오류 코드, 인증 규칙을 코드 기준으로 정리하는 것을 목표로 한다.

---

## 2. 범위

본 문서는 현재 구현된 사용자 기능 API 계약을 기준으로 한다.

API 범위는 다음과 같다.

1. 인증 API
2. 친구 API
3. 메시지 API
4. 위치 조회 및 저장 API
5. 출발 위치 검색 API
6. 저장된 출발 위치 API
7. 추천 결과 조회 API
8. 추천 길찾기 보조 API

본 문서의 기본 범위에서 제외하는 항목은 다음과 같다.

1. 닉네임 찾기
2. 비밀번호 재설정
3. 추천 결과 이력 저장 API
4. WebSocket 기반 실시간 채팅 API
5. 실시간 위치 추적 API
6. 운영용 헬스체크 API

### 2.1 현재 구현 대응 관계

현재 코드와 본 API 문서의 대응 관계는 다음과 같다.

1. 로그인과 회원가입 화면은 auth API 를 직접 호출한다.
2. friends 화면은 친구 목록 조회, 친구 검색, 친구 요청 생성, 요청 수락/거절 API 를 사용한다.
3. chat 화면은 메시지 조회/전송, 위치 조회/저장, 저장 위치 CRUD, 추천 조회 API 를 사용한다.
4. 나중에 만나기 흐름의 주소 검색은 location/search API 를 사용한다.
5. 추천 지도의 길찾기 카드와 외부 길찾기 진입 정보는 recommendations/routes API 를 사용한다.

## 3. 공통 규칙

### 3.1 기본 규칙

1. 모든 API 응답은 JSON 형식으로 반환한다.
2. 보호 API 는 요청 본문에 userId 를 받지 않고, JWT 쿠키 검증 결과의 currentUserId 를 기준으로 현재 사용자를 식별한다.
3. 클라이언트는 인증 토큰을 직접 저장하지 않고, 서버가 발급한 httpOnly 쿠키를 사용한다.
4. Kakao Local API 와 Kakao Mobility API 는 브라우저에서 직접 호출하지 않고 서버 Route Handler 에서만 호출한다.
5. 보호 API 는 JWT 검증 실패 시 401 UNAUTHORIZED 를 반환한다.

### 3.2 인증 및 쿠키 규칙

1. 쿠키 이름은 meetpoint_auth 로 고정한다.
2. JWT payload 는 userId, nickname, iat, exp 값을 포함한다.
3. JWT 는 JWT_SECRET 환경 변수로 서명하고 검증한다.
4. 쿠키 속성은 httpOnly, sameSite=lax, path=/ 를 기본으로 한다.
5. 운영 환경에서는 secure=true 로 설정한다.
6. 쿠키 만료 시간은 7일로 설정한다.
7. 로그아웃은 현재 쿠키 유무와 관계없이 인증 쿠키를 삭제한다.
8. 유효하지 않거나 만료된 쿠키는 즉시 삭제한다.

### 3.3 공통 응답 형식

성공 응답 형식:

```json
{ "ok": true, "data": {} }
```

오류 응답 형식:

```json
{
  "ok": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "사용자 안내 문구"
  }
}
```

### 3.4 공통 검증 규칙

1. nickname 은 trim 후 앞뒤 공백을 제거하고 내부 연속 공백은 한 칸으로 정규화한다.
2. nickname 은 정규화 후 2자 이상 12자 이하만 허용한다.
3. nickname 은 한글, 영문, 숫자, 공백만 허용한다.
4. nickname 비교와 중복 검사는 nickname_normalized 기준으로 수행하며 영문은 소문자로 정규화한다.
5. password 는 4자 이상 20자 이하만 허용하고 공백을 포함할 수 없다.
6. friendNickname 은 자기 자신의 nickname_normalized 와 같을 수 없다.
7. content 는 trim 후 1자 이상 500자 이하만 허용한다.
8. lat 는 -90 이상 90 이하, lng 는 -180 이상 180 이하만 허용한다.
9. friendId 와 departureLocationId 는 UUID 형식 문자열만 허용한다.
10. limit 는 생략 시 50, 최대 100까지만 허용한다.
11. after 와 afterId, before 와 beforeId 는 각각 한 쌍으로만 인정한다.
12. mode 는 now 또는 later 중 하나만 허용한다.
13. category 는 cafe, meal, fun 중 하나만 허용한다.
14. query 는 출발 위치 검색 시 2자 이상 문자열만 허용한다.
15. locationKind 는 recent 또는 preset 중 하나만 허용한다.
16. ownerParty 는 me 또는 friend 중 하나만 허용한다.
17. friendNickname 은 friend 소유 저장 위치에서만 사용하며 100자 이하 문자열이어야 한다.
18. scope 는 friend 또는 all_friends 중 하나만 허용한다.
19. departure 와 friendDeparture 는 label, lat, lng, source 를 모두 포함해야 하며 source 는 search, pin, saved 중 하나만 허용한다.
20. recommendations/routes 의 mode 는 bus, car, bike, walk 중 하나만 허용한다.

## 4. 공통 타입 계약

### 4.1 UserSummary

```ts
type UserSummary = {
    id: string;
    nickname: string;
    lat: number | null;
    lng: number | null;
    locationUpdatedAt: string | null;
};
```

### 4.2 FriendRelationState

```ts
type FriendRelationState =
    | "accepted"
    | "incoming_pending"
    | "outgoing_pending"
    | null;
```

### 4.3 MessageItem

```ts
type MessageItem = {
    id: string;
    senderId: string;
    receiverId: string;
    content: string;
    readAt: string | null;
    createdAt: string;
};
```

### 4.4 SavedDepartureLocation

```ts
type SavedDepartureLocation = {
    id: string;
    label: string;
    address: string | null;
    lat: number;
    lng: number;
    ownerParty: "me" | "friend";
    friendId: string | null;
    friendNickname: string | null;
    locationKind: "recent" | "preset";
    isSelected: boolean;
    lastUsedAt: string;
    createdAt: string;
    updatedAt: string;
};
```

### 4.5 DeparturePoint

```ts
type DeparturePoint = {
    label: string;
    lat: number;
    lng: number;
    source: "search" | "pin" | "saved";
};
```

### 4.6 RecommendationMode

```ts
type RecommendationMode = "now" | "later";
```

### 4.7 RecommendationCategory

```ts
type RecommendationCategory = "cafe" | "meal" | "fun";
```

### 4.8 ApiResponse

```ts
type ApiSuccess<T> = { ok: true; data: T };

type ApiError = {
    ok: false;
    error: {
        code: string;
        message: string;
    };
};

type ApiResponse<T> = ApiSuccess<T> | ApiError;
```

## 6. 엔드포인트 상세 명세

### 6.1 POST /api/auth/signup

설명:

1. nickname 과 password 를 검증한다.
2. nickname_normalized 기준 중복 사용자를 확인한다.
3. 사용자 생성 후 JWT 쿠키를 즉시 발급한다.

요청 예시:

```json
{
  "nickname": "홍길동",
  "password": "pass1234"
}
```

성공 응답 예시:

```json
{
  "ok": true,
  "data": {
    "user": {
      "id": "uuid",
      "nickname": "홍길동",
      "lat": null,
      "lng": null,
      "locationUpdatedAt": null
    }
  }
}
```

오류 코드:

1. INVALID_INPUT
2. CONFLICT_NICKNAME
3. INTERNAL_ERROR

### 6.2 POST /api/auth/login

설명:

1. nickname 과 password 를 검증한다.
2. nickname_normalized 기준 사용자를 조회한다.
3. password_hash 비교를 통과하면 JWT 쿠키를 발급한다.

오류 코드:

1. INVALID_INPUT
2. UNAUTHORIZED
3. INTERNAL_ERROR

### 6.3 POST /api/auth/logout

설명:

1. 현재 인증 상태와 관계없이 인증 쿠키를 삭제한다.
2. 성공 시 cleared=true 를 반환한다.

### 6.4 GET /api/friends

설명:

1. nickname 쿼리가 없으면 친구 목록과 받은 요청, 보낸 요청을 함께 반환한다.
2. nickname 쿼리가 있으면 해당 닉네임 사용자와 현재 관계 상태를 조회한다.
3. 검색 응답에서는 위치 정보를 마스킹한 친구 요약을 사용할 수 있다.

친구 목록 응답 예시:

```json
{
  "ok": true,
  "data": {
    "friends": [],
    "incomingRequests": [],
    "outgoingRequests": []
  }
}
```

검색 응답 예시:

```json
{
  "ok": true,
  "data": {
    "friend": {
      "id": "uuid",
      "nickname": "친구"
    },
    "relation": {
      "state": "outgoing_pending"
    }
  }
}
```

오류 코드:

1. INVALID_INPUT
2. INTERNAL_ERROR

### 6.5 POST /api/friends

설명:

1. friendNickname 을 검증한다.
2. 자기 자신 친구 추가를 차단한다.
3. 이미 accepted, outgoing_pending, incoming_pending 상태면 409 를 반환한다.
4. 가능할 때만 pending 친구 요청을 생성한다.

오류 코드:

1. INVALID_INPUT
2. FRIEND_NOT_FOUND
3. FRIEND_ALREADY_ACCEPTED
4. FRIEND_REQUEST_ALREADY_SENT
5. FRIEND_REQUEST_PENDING_FROM_TARGET
6. INTERNAL_ERROR

### 6.6 PATCH /api/friends

설명:

1. requestId 와 action 을 받아 받은 요청을 처리한다.
2. action 은 accept 또는 reject 만 허용한다.
3. accept 시 수락된 친구 요약을 함께 반환한다.

요청 예시:

```json
{
  "requestId": "uuid",
  "action": "accept"
}
```

오류 코드:

1. INVALID_INPUT
2. FRIEND_REQUEST_NOT_FOUND
3. INTERNAL_ERROR

### 6.7 DELETE /api/friends

설명:

1. friendId 를 받아 현재 친구 관계를 제거한다.
2. 채팅방 나가기 동작과 동일한 의미를 가진다.

오류 코드:

1. INVALID_INPUT
2. FRIEND_NOT_FOUND
3. INTERNAL_ERROR

### 6.8 GET /api/messages

설명:

1. friendId 는 필수이다.
2. after 와 afterId, before 와 beforeId 는 각각 함께 전달해야 한다.
3. 두 방향 메시지를 createdAt asc, id asc 기준으로 반환한다.
4. 응답에는 lastMessageCreatedAt, lastReadOwnMessage, pollingIntervalSec 이 포함된다.
5. 친구 관계가 없으면 403 FORBIDDEN_RELATION 을 반환한다.

오류 코드:

1. INVALID_INPUT
2. FORBIDDEN_RELATION
3. INTERNAL_ERROR

### 6.9 POST /api/messages

설명:

1. friendId 와 content 를 검증한다.
2. currentUserId 를 발신자로 고정한다.
3. 친구 관계가 없으면 저장할 수 없다.

오류 코드:

1. INVALID_INPUT
2. FORBIDDEN_RELATION
3. INTERNAL_ERROR

### 6.10 GET /api/location

설명:

1. 현재 사용자의 마지막 공유 위치를 조회한다.
2. locationShareScope 와 locationShareTargetUserId 를 함께 반환한다.
3. 새로고침 후 chat 화면 상태 복원에 사용한다.

### 6.11 POST /api/location

설명:

1. lat, lng, scope 를 검증한다.
2. scope 가 friend 인 경우 friendId 도 함께 검증한다.
3. 친구 관계가 없는 대상에게는 위치를 공유할 수 없다.
4. 저장 후 최신 위치와 공유 범위를 함께 반환한다.

요청 예시:

```json
{
  "lat": 37.5665,
  "lng": 126.978,
  "scope": "friend",
  "friendId": "uuid"
}
```

오류 코드:

1. INVALID_INPUT
2. FORBIDDEN_RELATION
3. INTERNAL_ERROR

### 6.12 GET /api/location/search

설명:

1. query 를 검증한 뒤 Kakao Local API 키워드 검색을 서버에서 대리 호출한다.
2. 검색 실패 시 KAKAO_API_FAILED 를 반환한다.

오류 코드:

1. INVALID_INPUT
2. KAKAO_API_FAILED
3. INTERNAL_ERROR

### 6.13 GET /api/location/departures

설명:

1. 현재 사용자 소유의 저장 위치만 조회한다.
2. preset 을 우선 정렬하고, 이후 recent 를 last_used_at 기준으로 정렬한다.
3. limit 기본값은 50이다.

### 6.14 POST /api/location/departures

설명:

1. label, address, lat, lng, locationKind 를 검증한다.
2. ownerParty 는 생략 시 me 를 사용한다.
3. ownerParty 가 friend 면 friendId 와 friendNickname 이 필수이다.
4. friend 저장 위치는 실제 친구 관계가 있을 때만 생성할 수 있다.

오류 코드:

1. INVALID_INPUT
2. FORBIDDEN_RELATION
3. INTERNAL_ERROR

### 6.15 PATCH /api/location/departures

설명:

1. departureLocationId, label, address, lat, lng 를 검증한다.
2. ownerParty 변경이 포함될 수 있다.
3. ownerParty 가 friend 이면 friendId, friendNickname 검증과 친구 관계 검증이 함께 필요하다.
4. 대상 위치가 없으면 404 NOT_FOUND 를 반환한다.

### 6.16 DELETE /api/location/departures

설명:

1. departureLocationIds 배열을 받는다.
2. 한 개 이상 UUID 가 필요하다.
3. 개별 삭제와 다건 삭제를 동일 엔드포인트로 처리한다.

### 6.17 POST /api/location/departures/use

설명:

1. departureLocationId 를 받아 last_used_at 을 갱신한다.
2. 현재 사용자 소유 위치에 대해서만 동작한다.
3. 대상이 없으면 404 DEPARTURE_NOT_FOUND 를 반환한다.

### 6.18 POST /api/recommendations

설명:

1. friendId, mode, category 를 검증한다.
2. later 모드일 때 departure 와 friendDeparture 를 함께 해석한다.
3. 친구 관계가 없으면 403 FORBIDDEN_RELATION 을 반환한다.
4. 위치가 부족하면 LOCATION_REQUIRED 를, later 입력이 부족하면 DEPARTURE_REQUIRED 를 반환한다.
5. Kakao Local 연동 실패 시 KAKAO_API_FAILED 를 반환한다.

요청 예시:

```json
{
  "friendId": "uuid",
  "mode": "later",
  "category": "meal",
  "departure": {
    "label": "강남역",
    "lat": 37.4979,
    "lng": 127.0276,
    "source": "search"
  },
  "friendDeparture": {
    "label": "건대입구역",
    "lat": 37.5404,
    "lng": 127.0692,
    "source": "saved"
  }
}
```

오류 코드:

1. INVALID_INPUT
2. FORBIDDEN_RELATION
3. LOCATION_REQUIRED
4. DEPARTURE_REQUIRED
5. KAKAO_API_FAILED
6. INTERNAL_ERROR

### 6.19 POST /api/recommendations/routes

설명:

1. destination, origins, mode 를 검증한다.
2. origins 는 1개 이상이어야 하고 각 origin 은 owner, label, lat, lng 를 포함해야 한다.
3. mode 가 car 이면 차량 경로 provider 를 사용하고, 나머지는 fallback 응답을 사용한다.
4. Kakao Mobility 연동 실패 시 KAKAO_MOBILITY_API_FAILED 를 반환한다.

오류 코드:

1. INVALID_INPUT
2. KAKAO_MOBILITY_API_FAILED
3. INTERNAL_ERROR

## 7. 후속 메모

1. 운영용 GET /api/health/supabase 는 현재 구현되어 있지만 사용자 기능 PRD 범위에서는 제외한다.
2. 추천 결과는 현재 계산형 응답 구조이므로 저장 API 는 만들지 않는다.
3. 메시지 읽음 처리, 친구 요청 수락, 저장 위치 선택 상태 갱신은 서비스 계층과 DB 제약을 함께 고려해야 한다.
4. 보호 API 호출 시 401 응답을 받으면 화면은 /login 으로 이동하는 흐름을 기본으로 한다.

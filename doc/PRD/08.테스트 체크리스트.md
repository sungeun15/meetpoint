# MeetPoint 테스트 체크리스트

## 1. 문서 목적

이 문서는 MeetPoint의 현재 구현을 기준으로, 무엇을 어떤 순서로 확인해야 하는지 정리한 테스트 체크리스트이다.

이전처럼 퍼블리싱 UI만 보는 문서가 아니라, 현재 실제로 연결된 인증, 친구, 메시지, 위치, 저장 위치, 추천, 지도, 배포 검증 흐름까지 포함하는 운영용 테스트 기준 문서로 사용한다.

---

## 2. 테스트 범위

포함 범위:

1. 랜딩, 로그인, 회원가입 화면 동작
2. JWT 쿠키 기반 인증과 보호 페이지 이동
3. 친구 요청, 수락, 거절, 삭제 흐름
4. 메시지 조회, 전송, 읽음 상태 반영
5. 현재 위치 공유와 저장된 출발 위치 CRUD
6. Kakao Map, Daum Postcode, Kakao Local 연동
7. 추천 결과 10개, 요약, 지도, 길찾기 카드
8. 모바일 전체화면 지도와 결과 시트 동작
9. 빌드, 타입, 배포 전 최종 점검

제외 범위:

1. WebSocket 기반 실시간 채팅
2. 백그라운드 위치 추적
3. 비밀번호 재설정
4. 추천 결과 이력 저장
5. 관리자 화면

---

## 3. 테스트 기본 원칙

### 3.1 우선순위

테스트는 아래 순서로 진행한다.

1. 정적 검증 명령이 통과하는지 확인한다.
2. 인증과 보호 페이지 이동이 정상인지 확인한다.
3. friends 와 chat 핵심 시나리오가 이어지는지 확인한다.
4. 지도와 추천 결과가 서로 동기화되는지 확인한다.
5. 모바일 전체화면 지도와 배포 환경까지 최종 확인한다.

### 3.2 권장 환경

1. local
2. preview
3. production 직전 최종 확인 환경

권장 순서:

1. local 수동 테스트
2. pnpm lint
3. pnpm type-check
4. pnpm build
5. 필요 시 외부 연동 스크립트 실행
6. preview 시나리오 검증

### 3.3 합격 기준

1. 핵심 사용자 시나리오가 local 또는 preview 에서 끝까지 이어진다.
2. 주요 보호 페이지와 보호 API가 인증 상태에 맞게 동작한다.
3. 추천 결과 목록, 요약, 지도 마커, 길찾기 카드가 함께 갱신된다.
4. 모바일 화면에서 전체화면 지도와 결과 시트 조작이 깨지지 않는다.
5. lint, type-check, build 중 치명적 실패가 없다.

## 4. 사전 준비

### 4.1 필수 환경 변수

현재 구현 기준으로 아래 값이 준비되어 있어야 한다.

1. NEXT_PUBLIC_SUPABASE_URL
2. NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
3. SUPABASE_SERVICE_ROLE_KEY
4. SUPABASE_DATABASE_URL
5. JWT_SECRET
6. NEXT_PUBLIC_KAKAO_MAP_APP_KEY
7. KAKAO_LOCAL_REST_API_KEY

운영 헬스체크까지 포함하면 아래 값도 필요하다.

1. CRON_SECRET

### 4.2 계정 및 데이터 준비

1. 로그인 가능한 테스트 계정 2개 이상 준비
2. 친구 요청을 주고받을 수 있도록 서로 다른 닉네임 준비
3. 메시지 송수신과 읽음 상태 확인용 테스트 대화 준비
4. 내 위치와 친구 위치를 각각 저장할 수 있는 브라우저 권한 허용 상태 준비
5. 저장된 출발 위치 테스트를 위한 주소 2개 이상 준비

### 4.3 외부 연동 준비

1. Kakao JavaScript 키에 local, preview, production 도메인이 등록되어 있어야 한다.
2. Daum Postcode 스크립트가 차단되지 않는 네트워크 환경이어야 한다.
3. Kakao Local REST API 키가 서버 환경에 설정되어 있어야 한다.

## 5. 실행 명령 체크

아래 명령은 테스트 시작 전 최소 1회 확인한다.

```bash
pnpm lint
pnpm type-check
pnpm build
```

외부 연동 확인이 필요하면 아래 스크립트를 추가로 실행한다.

```bash
pnpm run test:kakao:sdk
pnpm run test:kakao:local
pnpm run test:supabase
pnpm run test:supabase:schema
pnpm run test:supabase:table
```

상황에 따라 아래 스크립트를 사용한다.

```bash
pnpm run test:supabase:backfill-addresses
pnpm run test:supabase:cleanup
```

## 6. 핵심 통합 시나리오

### 6.1 시나리오

1. 비로그인 상태에서 / 진입 후 로그인 화면으로 이동한다.
2. 회원가입 또는 로그인으로 세션을 만든다.
3. /friends 에서 친구를 검색하거나 요청한다.
4. 상대 계정에서 요청을 수락한다.
5. 친구 카드로 /chat?friend={id} 상세 화면에 진입한다.
6. 메시지를 전송하고 읽음 상태를 확인한다.
7. 지금 만나기 모드에서 현재 위치를 공유하고 추천을 요청한다.
8. 추천 결과 목록, 요약, 지도 마커, 길찾기 카드가 함께 갱신되는지 확인한다.
9. 나중에 만나기 모드로 전환한다.
10. 검색, 핀 지정, 저장 위치 중 하나로 내 출발 위치와 친구 출발 위치를 설정한다.
11. 저장 위치를 새로 저장하거나 기존 저장 위치를 선택한다.
12. 추천을 다시 요청하고 모바일 전체화면 지도까지 확인한다.

### 6.2 기대 결과

1. 세션 상태에 따라 라우트 이동이 올바르게 분기된다.
2. 친구 요청 상태가 pending 에서 accepted 로 갱신된다.
3. 메시지 목록과 unread 상태가 서버 응답 기준으로 유지된다.
4. 위치 공유 시 users.location_updated_at 과 좌표 기반 UI가 갱신된다.
5. 저장 위치는 departure_locations 기반으로 생성, 조회, 선택된다.
6. 추천 응답은 summary, midpoint, places, routes 정보를 함께 반영한다.
7. 모바일 전체화면 지도에서 지도와 결과 시트가 모두 조작 가능하다.

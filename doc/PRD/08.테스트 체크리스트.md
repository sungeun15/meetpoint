# MeetPoint 테스트 체크리스트

## 1\. 문서 목적

이 문서는 MeetPoint의 현재 퍼블리싱 UI가 실제로 동작하는지 확인하기 위한 테스트 체크리스트 문서이다.

기획 문서, 화면 명세서, API 명세서, DB 문서에서 확정한 기준을 실제 테스트 항목으로 다시 풀어서, 구현 완료 후 무엇을 어떤 순서로 확인해야 하는지 명확히 정리하는 것을 목표로 한다.

현재 문서는 UI 소스 기준 수동 검증, 빌드 계열 검증, 외부 SDK 동작 확인을 우선 정리하고, 인증/API/DB 통합 테스트는 별도 체크 항목으로 분리한다.

역할 분담과 완료 상태는 WBS 문서에서 관리하며, 본 문서는 테스트 범위와 판정 기준만 다룬다.

## 3\. 테스트 기본 원칙

### 3.1 MVP 기준 우선순위

MeetPoint 테스트는 아래 순서를 기준으로 진행한다.

1.  랜딩, 로그인, 회원가입 화면이 의도한 UI 상태와 검증 문구를 보여 주는가
2.  friends 화면에서 친구를 로컬 상태로 추가하고 선택할 수 있는가
3.  chat 화면에서 메시지 전송, 위치 공유, 추천 입력 흐름이 이어지는가
4.  추천 결과 카드, 요약, 지도 패널이 함께 갱신되는가
5.  외부 SDK가 필요한 주소 검색과 핀 지정 레이어가 깨지지 않고 열리는가

즉, 테스트는 서버 저장 여부보다 현재 UI 시연 흐름이 끊기지 않고 끝까지 이어지는지를 우선 본다.

### 3.2 테스트 환경 원칙

테스트는 아래 환경 중 최소 1개 이상에서 수행한다.

1.  local 개발 환경
2.  preview 배포 환경

권장 순서는 아래와 같다.

1.  local에서 기능 단위 확인
2.  pnpm lint, pnpm build, pnpm type-check 확인
3.  필요 시 preview에서 통합 동작 확인

### 3.3 합격 기준

아래 조건을 만족하면 MVP 기준 통과로 본다.

1.  핵심 사용자 시나리오가 처음부터 끝까지 실패 없이 이어진다.
2.  주요 오류 상황에서 사용자 안내 문구가 나온다.
3.  추천 결과가 지도와 카드 양쪽에 반영된다.
4.  현재 UI 범위와 인증/API/DB 통합 범위가 테스트 문서에서 구분된다.

## 4\. 테스트 준비 항목

테스트 시작 전 아래 항목을 먼저 확인한다.

### 4.1 환경 변수

현재 UI 기준으로 우선 확인할 값은 아래와 같다.

1.  NEXT\_PUBLIC\_KAKAO\_MAP\_APP\_KEY
2.  필요 시 KAKAO\_LOCAL\_REST\_API\_KEY

메모:

1.  Kakao Map SDK 기반 화면과 핀 지정 레이어 확인에는 지도 앱 키가 필요하다.
2.  Supabase, JWT 관련 값은 현재 퍼블 UI 검증의 필수 조건이 아니라 별도 서버 연동 체크 항목이다.

### 4.2 데이터 준비

아래 조건이 준비되어 있어야 한다.

1.  initialFriends fixture가 기본 친구 목록으로 렌더링되어야 한다.
2.  initialChatMessages fixture가 기본 대화 목록으로 렌더링되어야 한다.
3.  initialSavedDepartures fixture가 저장 위치 선택용 데이터로 렌더링되어야 한다.
4.  /chat?friend={id} 형태의 상세 진입을 확인할 수 있어야 한다.

현재 단계에서는 DB 시드나 테이블 생성이 필수 준비 항목이 아니다.

별도 DB 연동 테스트를 진행할 때는 아래 중 하나가 추가로 준비되어 있어야 한다.

1.  Supabase SQL Editor 접근 가능 상태
2.  PostgreSQL 직접 접속 정보 준비
3.  Supabase CLI migration 환경 준비
4.  관리자용 내부 스크립트 준비

### 4.3 외부 연동 준비

1.  Kakao Map JavaScript 키 설정 완료
2.  Daum Postcode 스크립트 로드 가능 상태
3.  필요 시 Kakao Local REST API 키 설정 완료
4.  JavaScript SDK 도메인 등록 완료

## 5\. 핵심 사용자 시나리오 통합 테스트

이 항목은 가장 먼저 수행하는 대표 시나리오이다.

### 5.1 시나리오

1.  랜딩 화면에서 CTA preview toggle 을 전환한다.
2.  /login 또는 /signup 화면으로 이동해 입력 검증 문구를 확인한다.
3.  /friends 화면에서 새 친구 닉네임을 추가한다.
4.  친구 카드 또는 /chat?friend={id} 링크로 chat 상세 화면에 진입한다.
5.  메시지를 입력하고 전송해 로컬 대화 목록 갱신을 확인한다.
6.  지금 만나기 모드에서 위치 공유를 누른다.
7.  추천 버튼을 눌러 추천 요약, 장소 카드 10개, 지도 패널 전환을 확인한다.
8.  나중에 만나기 모드로 전환한다.
9.  주소 검색, 핀 지정, 저장 위치 중 하나 이상으로 내 출발 위치와 친구 출발 위치를 정한다.
10. 위치 저장 버튼으로 저장 위치 제목 입력 레이어를 연다.
11. 추천 버튼을 다시 눌러 나중에 만나기 기준 결과를 확인한다.

### 5.2 기대 결과

1.  랜딩 CTA가 preview 상태에 따라 /login 또는 /friends 로 분기된다.
2.  인증 화면은 입력값이 비어 있거나 비밀번호가 맞지 않을 때 검증 문구를 보여 준다.
3.  friends 화면에서 추가한 친구가 로컬 목록 상단에 반영된다.
4.  chat 상세 화면에서 선택한 친구 기준 헤더, 메시지, 상태 패널이 열린다.
5.  메시지가 로컬 목록에 즉시 반영되고 피드백 문구가 나온다.
6.  지금 만나기 모드에서 위치 공유 후 추천 버튼이 활성화된다.
7.  지금 만나기 추천 결과에서 더미데이터 기준 추천 카드 10개, 요약, 지도 패널이 표시된다.
8.  나중에 만나기 모드에서 출발 위치 입력 또는 저장 위치 선택이 가능하다.
9.  저장 위치 제목 입력 레이어에서 제목 입력 전 저장 버튼이 비활성화된다.
10. 나중에 만나기 추천 결과에서도 요약, 장소 카드, 지도 패널이 함께 갱신된다.

## 13\. 오류 및 예외 상황 테스트

### 13.1 인증 오류

1.  닉네임 없이 로그인 또는 회원가입 제출
2.  비밀번호 없이 로그인 또는 회원가입 제출
3.  회원가입 비밀번호 확인 불일치

기대 결과:

1.  입력 카드 내부에 검증 문구가 표시된다.
2.  화면 레이아웃은 깨지지 않는다.

### 13.2 네트워크 및 서버 오류

1.  Daum Postcode 로드 실패
2.  Kakao 지도 SDK 로드 실패
3.  핀 지정 검색 실패
4.  API 연동 실패

기대 결과:

1.  화면이 깨지지 않는다.
2.  오류 문구가 사용자 행동 위치 근처에 표시된다.
3.  재시도 가능 상태를 유지한다.

## 16\. 배포 전 최종 점검 항목

배포 전에는 아래 항목을 최소한 한 번 더 확인한다.

1.  랜딩 화면에서 CTA와 내비게이션 동작 확인
2.  랜딩 preview toggle 에 따른 CTA 목적지 확인
3.  친구 추가와 친구 목록 표시 확인
4.  friends 에서 chat 으로 상세 진입 확인
5.  채팅 로컬 반영과 조회 확인
6.  위치 공유와 저장 위치 레이어 확인
7.  추천 결과 카드 10개와 추천 기준 요약 표시 확인
8.  추천 전 안내 이미지와 추천 후 지도 패널 전환 확인
9.  Kakao Map, Daum Postcode 관련 환경 확인
10. pnpm lint 확인
11. pnpm build 확인
12. pnpm type-check 확인
13. 브라우저 콘솔과 서버 로그에 치명적 오류가 없는지 확인
